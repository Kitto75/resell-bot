# ربات مدیریت ریسلر برای پنل PasarGuard

ربات تلگرامی برای فروش و مدیریت اکانت از طریق ریسلرها. ریسلرها با موجودی خودشان از داخل تلگرام اکانت می‌سازند و تمدید می‌کنند، مدیر همه‌چیز را از یک پنل مدیریت می‌بیند و کنترل می‌کند. ربات با API پنل **PasarGuard** (هماهنگ با نسخه‌ی 5.4) کار می‌کند و همه‌ی متن‌ها، دکمه‌ها و گزارش‌ها فارسی هستند.

**فهرست:** [امکانات](#امکانات) · [نصب](#نصب) · [پیکربندی](#پیکربندی-env) · [اجرا با systemd](#اجرای-دائمی-با-systemd) · [راهنمای استفاده](#راهنمای-استفاده) · [بکاپ](#بکاپ) · [**بازیابی بکاپ**](#بازیابی-بکاپ-ریستور) · [به‌روزرسانی](#بهروزرسانی-ربات) · [عیب‌یابی](#عیبیابی) · [ساختار پروژه](#ساختار-پروژه)

## امکانات

**برای ریسلر**
- ساخت اکانت (نام کاربری، حجم، مدت) و تمدید اکانت، با نمایش خلاصه و تأیید دکمه‌ای. اکانت جدید با وضعیت `on_hold` ساخته می‌شود و مدت آن از اولین اتصال شروع می‌شود.
- فعال و غیرفعال‌سازی اکانت‌های خودش.
- ارسال QR Code و لینک اشتراک در **یک پیام**، همراه با نام و حجم (`testaccount | 35 GB | 31 Days`).
- «📋 لیست اکانت‌های من»: وضعیت و حجم هر اکانت. با فرستادن نام دقیق یک اکانت، لینک اشتراک و QR همان اکانت دوباره ارسال می‌شود.
- هنگام تمدید، آخرین برنامه‌ی مصرفی کاربر، آخرین زمان آنلاین و آخرین آپدیت سابسکریپشن نمایش داده می‌شود.
- درخواست شارژ با رسید متنی یا تصویری.
- هر ریسلر فقط به اکانت‌های خودش دسترسی دارد؛ مالکیت در فیلد note پنل با قالب `belongs to نام-ریسلر` ثبت می‌شود و سمت سرور بررسی می‌شود.

**برای مدیر**
- **مدیریت ریسلرها:** لیست صفحه‌بندی‌شده، «کارت ریسلر» با همه‌ی عملیات (ویرایش نام/قیمت/وضعیت، موجودی، آیدی‌های تلگرام، تراکنش‌ها، گروه‌ها، یوزرها، محدودیت‌ها) و حذف (بایگانی یا حذف کامل).
- افزودن ریسلر با آیدی عددی یا یوزرنیم تلگرام. هر ریسلر می‌تواند چند آیدی تلگرام داشته باشد که همگی از یک موجودی مشترک مصرف می‌کنند.
- **محدودیت‌ها:** حداکثر روز اعتبار و حداقل/حداکثر حجم؛ همگانی یا اختصاصی برای هر ریسلر.
- **دسترسی گروه‌ها:** مشخص می‌کند هر ریسلر با کدام گروه‌های PasarGuard می‌تواند اکانت بسازد.
- **تنظیمات تمدید:** حالت «افزایشی» (حجم و روز به مقدار فعلی اضافه شود) یا «ریست و جایگزینی» (مصرف صفر و مقدار جدید جایگزین شود).
- **تنظیمات سابسکریپشن:** ارسال لینک اشتراک به‌صورت Mono (کپی با یک لمس) روشن یا خاموش.
- ساخت، تمدید، فعال/غیرفعال‌سازی و حذف مستقیم هر کاربر بدون کسر از موجودی ریسلر.
- «👥 یوزرهای ریسلر»: غیرفعال یا فعال‌سازی گروهی همه‌ی اکانت‌های یک ریسلر.
- جستجوی سریع هر کاربر با فرستادن نام او (یا `/user نام`) و دکمه‌ی QR Code زیر آن.
- تأیید یا رد درخواست‌های شارژ با یک کلیک.
- غیرفعال کردن ریسلر همراه با پیام اختیاری که به او نمایش داده می‌شود (یا سکوت کامل ربات).
- **حالت تعمیرات** برای مسدود کردن موقت کاربران غیرمدیر.

**گزارش‌ها**
- گزارش عملیات ساخت و تمدید برای مدیر، و فهرست تراکنش‌ها به‌صورت کارت‌های مرتب با تاریخ شمسی (به وقت تهران).
- **PDF دسته‌بندی‌شده** (شارژ و افزایش، کاهش و تنظیم، ساخت، تمدید) برای همه‌ی ریسلرها یا یک ریسلر مشخص، در بازه‌ی ۷ روز، ۳۰ روز، ماه جاری یا کل سوابق.
- **PDF وضعیت لحظه‌ای ریسلرها:** موجودی، تعداد اکانت‌ها به تفکیک وضعیت، گروه‌ها، محدودیت‌ها و آیدی‌های تلگرام.

**بکاپ**
- بکاپ دستی و زمان‌بندی‌شده از دیتابیس برای مدیرها، با امکان ارسال از یک بات جداگانه. جزئیات در [بخش بکاپ](#بکاپ).

## نصب

پیش‌نیازها: سرور لینوکس (Ubuntu پیشنهاد می‌شود)، **Python 3.10 یا بالاتر**، توکن ربات از [BotFather](https://t.me/BotFather) و یک حساب ادمین در پنل PasarGuard.

```bash
git clone <your-repo-url> /root/resell-bot
cd /root/resell-bot

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
nano .env                      # مقدارها را طبق بخش بعد پر کنید
chmod 600 .env                 # توکن‌ها فقط برای خودتان خوانا باشد

python3 -m alembic upgrade head   # ساخت جدول‌های دیتابیس (اجباری، ربات خودش این کار را نمی‌کند)
python3 run.py                    # اجرای آزمایشی؛ با Ctrl+C متوقف می‌شود
```

**فونت فارسی برای PDF:** گزارش‌های PDF به یک فونت فارسی روی سرور نیاز دارند.

```bash
apt install -y fonts-vazirmatn      # اگر در نسخه‌ی اوبونتوی شما نبود: apt install -y fonts-dejavu-core
```
یا مسیر یک فایل TTF دلخواه را در `.env` با `PDF_FONT_PATH=` بدهید. بدون فونت، فقط ساخت PDF خطا می‌دهد و بقیه‌ی ربات سالم کار می‌کند.

## پیکربندی (`.env`)

| متغیر | الزامی | توضیح |
|---|---|---|
| `BOT_TOKEN` | بله | توکن ربات از BotFather |
| `ADMIN_IDS` | بله | آیدی عددی مدیرها، با ویرگول جدا شود: `123456789,987654321` |
| `MARZBAN_BASE_URL` | بله | آدرس پنل PasarGuard، مثل `https://panel.example.com` |
| `MARZBAN_USERNAME` | بله | نام کاربری ادمین پنل |
| `MARZBAN_PASSWORD` | بله | رمز ادمین پنل |
| `DATABASE_URL` | خیر | پیش‌فرض `sqlite+aiosqlite:///bot.db` (فایل `bot.db` کنار پروژه) |
| `TIMEZONE` | خیر | پیش‌فرض `Asia/Tehran`؛ برای تاریخ‌ها و زمان‌بندی بکاپ |
| `LOG_LEVEL` | خیر | پیش‌فرض `INFO` |
| `PDF_FONT_PATH` | خیر | مسیر فونت فارسی (TTF) برای PDF؛ خالی یعنی جستجوی فونت‌های سیستم |
| `DEFAULT_LANGUAGE` | خیر | فعلاً در کد استفاده نمی‌شود |

- نام متغیرهای `MARZBAN_*` قدیمی است، ولی به **پنل PasarGuard** شما اشاره می‌کند.
- حساب پنل باید دسترسی ساخت، ویرایش و حذف کاربر داشته باشد (ادمین کامل).
- فقط SQLite پشتیبانی می‌شود (بکاپ و بازیابی هم برای SQLite نوشته شده‌اند). اگر مسیر دیگری بدهید، مثلاً `sqlite+aiosqlite:////root/data/bot.db` (چهار اسلش یعنی مسیر مطلق)، همان مسیر ملاک است.

## اجرای دائمی با systemd

با systemd ربات در پس‌زمینه اجرا می‌شود، بعد از خطا دوباره بالا می‌آید و بعد از ریبوت سرور خودکار شروع می‌شود. مثال‌ها فرض می‌کنند پروژه در `/root/resell-bot` و کاربر `root` است.

```bash
nano /etc/systemd/system/resell-bot.service
```

```ini
[Unit]
Description=Resell Bot Telegram Service
After=network.target

[Service]
WorkingDirectory=/root/resell-bot
ExecStart=/root/resell-bot/.venv/bin/python /root/resell-bot/run.py
Restart=always
RestartSec=5
User=root
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

`WorkingDirectory` مهم است: `.env` و مسیر نسبی `bot.db` از همان پوشه خوانده می‌شوند.

```bash
systemctl daemon-reload
systemctl enable --now resell-bot     # فعال‌سازی و اجرا
systemctl status resell-bot           # باید active (running) باشد
journalctl -u resell-bot -f           # لاگ زنده
systemctl restart resell-bot          # بعد از هر تغییر تنظیمات یا کد
systemctl stop resell-bot             # توقف
```

## راهنمای استفاده

### دستورها

| دستور | چه کسی | کار |
|---|---|---|
| `/start` | همه | باز کردن منوی اصلی (برای مدیر، پنل مدیریت) |
| `/user نام` | مدیر | اطلاعات سرویس یک کاربر + دکمه‌ی «QR Code». فرستادن خود نام کاربری هم همین کار را می‌کند (فقط وقتی مدیر وسط یک فرآیند دیگر نیست) |
| `/reseller نام` | مدیر | باز کردن مستقیم کارت یک ریسلر؛ با نام، آیدی عددی یا یوزرنیم. بدون نام، لیست ریسلرها |
| `/add_reseller` | مدیر | افزودن ریسلر |
| `/maintenance` | مدیر | حالت تعمیرات |

### شروع کار مدیر
1. مدیر `/start` می‌زند و **«➕ افزودن ریسلر»** را انتخاب می‌کند: آیدی عددی یا `@یوزرنیم`، نام نمایشی، موجودی اولیه و قیمت هر گیگابایت (تومان).
2. تبدیل یوزرنیم به آیدی عددی معمولاً فقط وقتی ممکن است که آن شخص قبلاً یک‌بار ربات را `/start` کرده باشد (محدودیت تلگرام). در غیر این صورت آیدی عددی را مستقیم وارد کنید.
3. از **«🌐 دسترسی گروه‌ها»** تعیین کنید ریسلر با کدام گروه‌های PasarGuard اکانت بسازد. حالت پیش‌فرض «همه گروه‌ها» است.
4. اگر خواستید از **«👥 مدیریت ریسلرها ← 🚦 محدودیت‌های همگانی»** سقف روز و بازه‌ی حجم را تعیین کنید.

### محدودیت‌ها
- **حداکثر روز:** ریسلر هر مقدار کمتر یا مساوی را می‌تواند بدهد.
- **حداقل و حداکثر حجم:** حجم باید داخل بازه باشد.
- روی ساخت و تمدید ریسلر اعمال می‌شود، و در مرحله‌ی تأیید هم دوباره بررسی می‌شود. ساخت و تمدید خود مدیر محدود نیست.
- تنظیم **همگانی** برای همه‌ی ریسلرها اعمال می‌شود. در «کارت ریسلر ← 🚦 محدودیت‌ها» می‌توانید برای یک ریسلر مقدار **اختصاصی** بدهید. با هر ذخیره‌ی همگانی یک مورد، همان مورد برای همه یکسان می‌شود و مقدار اختصاصی‌اش پاک می‌شود.

### غیرفعال و حذف ریسلر
- **غیرفعال‌سازی:** ربات می‌پرسد پیامی برای ریسلر نمایش داده شود یا نه. اگر متنی بدهید، آن متن به هر پیام یا دکمه‌ی ریسلر جواب داده می‌شود؛ اگر «بدون پیام» را بزنید، ربات ساکت می‌ماند.
- **حذف:** «📦 بایگانی» برگشت‌پذیر است و موجودی و تراکنش‌ها را نگه می‌دارد. «🗑 حذف کامل» همه‌ی سوابق ریسلر را از دیتابیس ربات پاک می‌کند و آیدی تلگرامش آزاد می‌شود. در هر دو حالت اکانت‌های ساخته‌شده در پنل دست نمی‌خورند.

### گزارش PDF
از پنل مدیریت «📄 گزارش PDF»: «همه ریسلرها» را بزنید، یا فقط نام یا یوزرنیم یک ریسلر را بفرستید تا گزارش تکی همان ساخته شود. گزارش وضعیت لحظه‌ای در «مدیریت ریسلرها ← 📊 گزارش وضعیت ریسلرها (PDF)» است.

## بکاپ

دیتابیس ربات (فایل SQLite) شامل ریسلرها، موجودی‌ها، تراکنش‌ها، فهرست اکانت‌های هر ریسلر و تنظیمات (محدودیت‌ها، پیام‌ها و ...) است. اکانت‌های کاربران داخل خود پنل PasarGuard هستند، نه دیتابیس ربات.

**گرفتن بکاپ:** پنل مدیریت ← **💾 بکاپ**
- «دریافت بکاپ الان»: ارسال فوری.
- «فعال‌سازی بکاپ» و «تغییر فاصله زمانی»: بکاپ خودکار (فاصله به دقیقه، پیش‌فرض ۶۰ دقیقه). بکاپ خودکار به‌صورت پیش‌فرض خاموش است.
- «🤖 بات بکاپ»: اگر بات اصلی شلوغ است، توکن یک بات دیگر (از BotFather) را بدهید تا فایل‌های بکاپ فقط از آن ارسال شوند. ابتدا داخل آن بات `/start` بزنید. پیام حاوی توکن بلافاصله حذف می‌شود. اگر ارسال با آن بات شکست بخورد، بکاپ با بات اصلی ارسال می‌شود تا گم نشود.

**محتوای فایل ZIP** (نام فایل با تاریخ شمسی است، مثل `backup-1405-07-25-12-42.zip`):

```text
backup-1405-07-25-12-42.zip
├── backup-1405-07-25-12-42.db    ← دیتابیس
├── .env                          ← تنظیمات و توکن‌ها (اگر خوانا باشد)
└── backup_info.txt               ← زمان ساخت و فایل‌های داخل بکاپ
```

> ⚠️ فایل ZIP شامل `.env` است، یعنی **توکن ربات و رمز پنل**. آن را فقط در جای امن نگه دارید و هرگز عمومی آپلود نکنید.

چند بکاپ تاریخ‌دار نگه دارید و گهگاه یکی را روی سیستم دیگر (نه فقط تلگرام) ذخیره کنید.

**بکاپ دستی از سرور** (ربات را متوقف کنید تا فایل در حین نوشتن کپی نشود):

```bash
systemctl stop resell-bot
mkdir -p /root/backups
cp /root/resell-bot/bot.db /root/backups/bot-$(date +%F-%H%M).db
systemctl start resell-bot
```

## بازیابی بکاپ (ریستور)

اگر دیتابیس خراب شد، اشتباهی پاک شد یا باید به نسخه‌ی قبلی برگردید، با همین ترتیب عمل کنید. کل کار چند دقیقه است. فرض: پروژه در `/root/resell-bot`، سرویس `resell-bot` و فایل بکاپ `/root/backup-1405-07-25-12-42.zip` است. فایل ZIP را از چت تلگرام دانلود و روی سرور آپلود کنید.

### بازیابی سریع (همان سرور)

```bash
cd /root/resell-bot
BACKUP=/root/backup-1405-07-25-12-42.zip      # ← مسیر بکاپ خودتان

# ۱) توقف ربات و نسخه‌ی اضطراری از دیتابیس فعلی (برای برگشت از ریستور)
systemctl stop resell-bot
[ -f bot.db ] && cp bot.db "bot.db.before-restore-$(date +%F-%H%M)"

# ۲) باز کردن بکاپ (بدون نیاز به نصب unzip) و بررسی سلامت آن
rm -rf /tmp/restore && python3 -m zipfile -e "$BACKUP" /tmp/restore
python3 -c "import glob,sqlite3; f=glob.glob('/tmp/restore/*.db')[0]; print(f, '->', sqlite3.connect(f).execute('PRAGMA integrity_check').fetchone()[0])"
#    باید «ok» چاپ شود. اگر چیز دیگری بود، سراغ بکاپ قدیمی‌تر بروید.

# ۳) جایگزینی دیتابیس
cp /tmp/restore/backup-*.db bot.db
rm -f bot.db-wal bot.db-shm bot.db-journal

# ۴) هماهنگ کردن ساختار دیتابیس با نسخه‌ی فعلی کد (برای بکاپ قدیمی لازم است، برای بکاپ جدید بی‌ضرر است)
source .venv/bin/activate
python3 -m alembic upgrade head

# ۵) اجرا و بررسی
systemctl start resell-bot
journalctl -u resell-bot -n 30 --no-pager
```

اگر `DATABASE_URL` شما به مسیر دیگری اشاره می‌کند، به‌جای `bot.db` در دستورها همان مسیر را بنویسید. اگر محیط مجازی (`.venv`) ندارید، خط `source` را حذف کنید.

### بازیابی روی سرور جدید

وقتی سرور قبلی کاملاً از دست رفته است:

```bash
apt update && apt install -y python3 python3-venv python3-pip git
git clone <your-repo-url> /root/resell-bot && cd /root/resell-bot      # یا کد پروژه را کپی کنید
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 -m zipfile -e /root/backup-1405-07-25-12-42.zip /tmp/restore
ls -a /tmp/restore                      # فایل‌های مخفی را هم می‌بیند؛ باید .env و .db را ببینید
cp /tmp/restore/.env .env && chmod 600 .env     # فقط اگر .env داخل بکاپ بود؛ وگرنه از .env.example بسازید
cp /tmp/restore/backup-*.db bot.db
python3 -m alembic upgrade head
python3 run.py                          # تست دستی؛ با Ctrl+C ببندید
```

سپس سرویس systemd را طبق [بخش systemd](#اجرای-دائمی-با-systemd) بسازید. **قبل از روشن کردن ربات روی سرور جدید، نمونه‌ی قبلی را (اگر هنوز بالاست) خاموش کنید**؛ دو ربات با یک توکن هم‌زمان کار نمی‌کنند و خطای `terminated by other getUpdates request` می‌دهند.

### بعد از ریستور چک کنید
1. `systemctl status resell-bot` باید `active (running)` باشد و لاگ خطای `Traceback` نداشته باشد.
2. با حساب مدیر `/start` بزنید و «👥 مدیریت ریسلرها ← 📋 لیست ریسلرها» را باز کنید؛ موجودی چند ریسلر را بررسی کنید.
3. بلافاصله یک بکاپ تازه بگیرید («💾 بکاپ ← دریافت بکاپ الان»).

### ریستور چه چیزی را برنمی‌گرداند
- هر تغییری که **بعد از زمان بکاپ** انجام شده باشد از بین می‌رود: شارژها، تراکنش‌ها و تغییر موجودی‌ها، ریسلرهای جدید و تنظیمات. اگر لازم بود، موجودی‌ها را دستی از «کارت ریسلر ← 💰 موجودی» اصلاح کنید.
- اکانت‌هایی که بعد از زمان بکاپ ساخته شده‌اند داخل پنل PasarGuard هستند و با note مالکیت‌شان قابل تمدید باقی می‌مانند، ولی در «لیست اکانت‌های من» و عملیات گروهی «یوزرهای ریسلر» (که از فهرست داخل دیتابیس ربات می‌خوانند) دیده نمی‌شوند.
- اگر ریستور اشتباه بود، همان نسخه‌ی اضطراری `bot.db.before-restore-...` را با همین روش برگردانید.

## به‌روزرسانی ربات

```bash
cd /root/resell-bot
systemctl stop resell-bot
cp -r /root/resell-bot /root/resell-bot.backup           # نسخه‌ی اضطراری از کل پروژه

# کد را به‌روز کنید: git pull   یا اعمال پچ:
patch -p1 --dry-run < update.patch     # فقط تمرین، چیزی تغییر نمی‌کند
patch -p1 < update.patch               # اعمال واقعی

source .venv/bin/activate
pip install -r requirements.txt        # اگر وابستگی جدیدی اضافه شده باشد
python3 -m alembic upgrade head        # اگر ساختار دیتابیس تغییر کرده باشد (اگر نبود، بی‌ضرر است)
systemctl start resell-bot
```

- اگر پچ برای فایل‌هایی که روی سرور ندارید (مثلاً پوشه‌ی `tests`) خطای `can't find file to patch` داد، بقیه‌ی فایل‌ها پچ شده‌اند. با `git apply --exclude='tests/*' update.patch` این خطا پیش نمی‌آید.
- پچ نیمه‌کاره را دوباره اجرا نکنید؛ `patch` پیام `Reversed (or previously applied) patch detected` می‌دهد و با جواب مثبت تغییرات را برمی‌گرداند.
- `patch -p1 -R < update.patch` پچ را برمی‌گرداند.

## عیب‌یابی

اول لاگ را ببینید:

```bash
journalctl -u resell-bot -n 100 --no-pager
```

| علامت | علت و راه‌حل |
|---|---|
| `ModuleNotFoundError` | پکیج‌ها با پایتونی نصب نشده‌اند که سرویس استفاده می‌کند. مسیر پایتون را در `ExecStart` ببینید و با همان `pip install -r requirements.txt` بزنید. |
| سرویس سریع متوقف می‌شود یا `.env` پیدا نمی‌شود | `WorkingDirectory` باید دقیقاً پوشه‌ی پروژه باشد؛ مقدارهای `.env` را هم بررسی کنید. |
| `no such table` | `python3 -m alembic upgrade head` را اجرا کنید. |
| `terminated by other getUpdates request` | نمونه‌ی دیگری از ربات با همین توکن در حال اجراست. یکی را خاموش کنید. |
| خطای 401 یا اتصال به پنل | `MARZBAN_BASE_URL`، نام کاربری و رمز ادمین پنل را بررسی کنید و ببینید سرور به پنل دسترسی دارد. |
| ساخت PDF خطا می‌دهد | فونت فارسی نصب نیست؛ بخش [نصب](#نصب) را ببینید. |
| ریسلری به ربات پاسخ نمی‌دهد | ممکن است غیرفعال یا بایگانی باشد (بدون پیام)، یا حالت تعمیرات روشن باشد. |
| ساخت اکانت ناموفق است و در لاگ `No PasarGuard groups are available` می‌بینید | در پنل گروه فعالی نیست یا گروه‌های مجاز ریسلر با گروه‌های فعال پنل نمی‌خواند؛ «🌐 دسترسی گروه‌ها» را بازبینی کنید. |

## ساختار پروژه

```text
run.py                 نقطه‌ی شروع
alembic/               مهاجرت‌های دیتابیس
app/
├── handlers/          جریان‌های گفت‌وگو: مدیر، ریسلر، جستجوی مدیر، امکانات تکمیلی مدیر
├── keyboards/         دکمه‌های inline
├── services/          ارتباط با پنل، صورتحساب، گزارش و PDF، بکاپ، محدودیت‌ها، ارسال QR
├── database/          مدل‌ها، نشست دیتابیس، repositoryها
├── middlewares/       احراز هویت، ریسلر غیرفعال، حالت تعمیرات
├── states/            وضعیت‌های FSM
└── utils/             قالب‌بندی و لاگ
```

مالکیت اکانت‌ها با note پنل (`belongs to نام-ریسلر`) تعیین می‌شود؛ پس نام نمایشی ریسلر را بعد از ساخت اکانت‌ها بی‌دلیل تغییر ندهید.
